# Physical Test Scene — execution plan

状态：核心实现已落地（2026-09-06）。目标：在现有项目中提供可编辑、可重复运行的 3D 物理测试场景，用来测试 parts movement、碰撞、机械连接和传感器交互。

当前实现入口是 `Physical Test` workspace。Rapier runtime、物理文档保存、真实 AVR adapter、Arduino↔物理固定时钟和无渲染 test-case runner 已经接入；剩余增强项（曲线/CSV 导出、复杂 collider 编辑器、性能基准面板）不改变首版数据归属和运行时接口。

## 1. 产品目标与首版范围

新增独立的 **Physical Test** 工作区入口，复用现有 3D 资源、相机、选取和装配编辑能力。场景可以只有机械零件，也可以引用当前 Board 的 Arduino 和执行器。

用户流程：创建测试场景 → 放入零件和障碍物 → 设置安装位置、质量、碰撞体与关节 → 手动驱动或运行 sketch → 观察实际运动和反馈 → 暂停、单步、重置 → 保存测试案例。

首版交付：

- 地面、固定支架、立方体、球、简单连杆，以及 GLB/STL 零件。
- 显式 fixed / dynamic / kinematic 刚体类型，质量、摩擦、恢复系数。
- 固定连接、旋转关节、滑动关节；轴、两侧锚点、限位和驱动参数。
- Servo、stepper、DC motor 三种执行器的机械测试，区分命令值与实际值。
- 接触/触发区域、机械限位输入、3D 距离查询与 Arduino 反馈。
- Edit / Running / Paused、单步、重置、慢速运行；手动命令和程序驱动二选一。
- 碰撞体和关节调试显示、运动曲线、事件记录、测试案例及结果导出。

首版以刚体行为和控制逻辑验证为精度目标。齿轮啮合细节、柔性材料、真实线缆张力、电机热模型、断裂、完整电磁耦合列为后续扩展。机械参数未校准时应在零件参数中标明“示例参数”，不能把结果当作硬件额定性能。

## 2. 已有能力与缺口（代码审查依据）

| 现有文件 | 已有能力 | 本计划需要的改动 |
| --- | --- | --- |
| `breadboard-3d/physics-context.tsx` | Rapier、1/60 固定步长、休眠 | 从画面驱动改成明确的仿真时钟；当前重力为视觉效果使用的 -5000 mm/s² |
| `physics-imports.tsx` | 导入模型动态刚体、凸包、拖拽 | 显式刚体配置；测试中的拖拽不自动写回初始姿态 |

| `animation-driver.tsx` | Servo、stepper、DC motor 和绑定动画 | 机械测试中由物理实际姿态驱动显示，禁止动画与物理重复写同一个节点 |
| `schemas/src/assembly.ts` | mm 装配坐标、parent、rotate/slide 动画绑定 | 新增独立物理配置；现有 joint 不是两个刚体之间的约束 |
| `simulator/sensor-inputs.ts` | 外设输入与 2D 环境距离 | 增加 3D 世界查询输入，并明确 2D/3D 输入提供者互斥 |

额外回归点：当前 follower 主要按位置变化唤醒，纯旋转需要覆盖；碰撞盒不能把世界 AABB 尺寸当作正确的局部碰撞形状；stepper 也需纳入统一执行器路径。

沿用 Three.js / React Three Fiber / Rapier。官方文档确认 Rapier 提供刚体、关节及关节驱动，React Three Rapier 提供手动步进能力；实际实现前须核对锁定版本的接口与力矩限制支持。

参考：[Rapier joints](https://rapier.rs/docs/user_guides/javascript/joints/)、[rigid bodies](https://rapier.rs/docs/user_guides/javascript/rigid_bodies/)、[React Three Rapier manual stepping](https://github.com/pmndrs/react-three-rapier#manual-stepping)。

## 3. 数据归属与场景结构

首版一个 project 对应一个可选 `physicalScene`，逻辑上独立，不要求先完成 Arduino/Scene 物理拆包。后续多场景另行扩展。

建议的持久化内容：

| 数据 | 内容 |
| --- | --- |
| 场景设置 | schemaVersion、重力、固定步长、求解配置 |
| bodies | 稳定 ID、来源引用、初始姿态、刚体类型、质量/惯量策略 |
| colliders | 所属 body、局部姿态、形状、尺寸、摩擦、恢复系数、碰撞组 |
| joints | bodyA/bodyB、双方局部锚点、轴、类型、限位、驱动配置 |
| actuators | joint 引用、零点/方向、命令来源、速度/力矩或推力限制 |
| sensors | 安装 body、局部位置和方向、量程、采样周期、输入映射 |
| testCases | 初始配置引用、定时输入、执行时长、断言与容差 |

运行时单独保存：物理 handles、实际位置/速度、接触、实际关节角、命令队列、采样值、仿真时间和测量结果。它们不进入自动保存或编辑 undo 历史。

场景实例引用 `componentId`、`assemblyBodyId` 或 assetId。视觉资源继续由现有 asset/assembly 拥有；物理场景拥有测试实例的初始世界姿态。显式导入/刷新当前装配，开始运行时冻结源 revision 和资源版本，编辑器改动不会悄悄改变正在运行的案例。引用丢失时给出修复入口，不静默删除。

已有 assembly 保持原样；只有显式“创建物理测试场景”才生成新的物理配置。不要把已有 rotate/slide 动画绑定自动升级为受力关节，也不要把视觉 parent 自动当成机械连接。

## 4. 单位、模型与碰撞体

- 编辑器保持 mm；物理世界统一使用 m、kg、s、rad、N、N·m。转换集中在场景构建/显示 adapter，包括位置、速度、长度限位和输入输出。
- 默认重力为 -9.81 m/s²；测试案例可以显式覆盖。世界使用 Y-up。
- 区分视觉层级和刚体连接。每个物理 body 有明确世界姿态；导入模型的 node/pivot、upAxis 和缩放先规范化，再生成 collider。
- 动态物体优先使用 box/sphere/capsule 或复合凸形；凹形机械结构用多个凸体表达。静态环境可使用三角网格。
- 默认单凸包只能作为预览建议：例如 U 形夹爪的中间空隙必须保留，不能被凸包填平。
- 零件质量显式配置；避免多个 collider 重复添加质量。记录质心/惯量自动计算还是手动配置。
- 限制动态物体不合理的薄片、极端质量比和负/零缩放；显示具体修复信息。编辑缩放时重新生成碰撞体并重建运行世界。
- 对高速、小尺寸物体选择性启用 CCD；相连刚体按关节规则过滤接触，不能全局关闭所有相邻零件碰撞。

## 5. 运行时与唯一姿态写入者

建议模块：

```text
schemas/physical-scene          场景、测试案例与版本化格式
app/physical-scene/runtime      构建/销毁世界、固定步进、重置、事件、测量
app/physical-scene/adapters     Rapier、Board 外设、单位转换、资源规范化
app/physical-scene/editor       场景树、参数面板、关节编辑、控制栏
app/physical-scene/testing      定时输入、断言、结果与回归场景
breadboard-3d                   复用视觉模型、相机、选取、资源加载
```

运行时接口至少覆盖 load、start、pause、step、reset、command、snapshot、dispose。实现可在 app 内开始，核心不依赖 React、DOM 或 WebGL，供无渲染物理测试复用。

- Edit：编辑工具修改持久化初始姿态。
- Running/Paused：物理世界拥有 dynamic body 的实际姿态；渲染读取并插值。
- Kinematic：仅用于明确指定的外部运动平台等，不用于宣称受力的 servo 输出轴。
- Reset：恢复初始世界和外设/控制器状态，清除速度、接触历史、输入队列、测量、累积时间；恢复可通过重建世界保证。
- “将当前姿态作为初始状态”必须是显式操作，暂停后执行，并作为一个可撤销编辑保存。
- 运行时鼠标拖拽用受限弹簧/约束施力，记录为外部输入；暂停时定位视为测试配置编辑，重置后才启动新的运行。
- 场景切换、退出工作区和重载资源必须释放 physics world、订阅和事件队列。

## 6. Arduino 与机械世界的时间协调

由一个协调器推进仿真时间。机械默认 1/120 s 固定 tick（先测性能）；渲染频率可以变化。CPU/外设保留更细的内部时钟，不把所有脉冲降采样成每 tick 一个布尔值。

每个机械 tick：

1. 应用带时间戳的手动输入，以及上一个 tick 锁存的传感器反馈。
2. 将 MCU/外设推进至当前 tick 终点，收集期间的 actuator 命令、STEP/DIR 边沿或电机驱动状态。
3. 更新执行器控制器，计算有上限的力/力矩，推进物理世界。
4. 从实际姿态生成接触、限位和距离测量，锁存到下一个 tick；记录指标。
5. 发布只读渲染快照；显示帧不推进另一套机械积分。

必须记录这一 tick 反馈延迟；更高采样需求使用子步或专门采样策略。暂停、断点、单步和慢放同时控制 MCU 与机械时钟。落后于实时速度时限制每帧追赶量并显示实际速度，保留仿真时间顺序；后台标签页暂停，不恢复后一次补算巨大时间差。

可独立使用 Manual 模式测试机械；Sketch 模式通过现有源码读取 adapter 接入。一个 actuator 同时只接受一个驱动来源。将来 `ProgramSource` 迁移只需替换该 adapter，本计划不依赖其先完成。

## 7. 执行器与传感器行为

| 类型 | 命令 | 机械实现与测量 |
| --- | --- | --- |
| Servo | 目标角 | 有限速度/力矩的位置控制；记录实际角、误差、饱和；被挡住时允许到不了目标 |
| Stepper | STEP/DIR 或手动步数 | 累积目标步数并保留实际轴角；有限力矩驱动，记录跟随误差；首版误差不能直接当作经校准的真实丢步预测 |
| DC motor | 电压/PWM 对应驱动力或简化命令 | 由物理世界积分实际轴速/惯量；现有 peripheral 的转子积分需关闭或改为机械反馈 adapter，避免两份惯量模型 |
| Limit/contact | 接触/触发区域 | 输出接触状态、事件时间，可选稳定时间/去抖；映射到输入引脚或已有开关输入通路 |
| Distance | 3D 世界姿态与量程 | 对碰撞体查询，过滤自身/安装体；输出距离或无回波，接入现有 ultrasonic 外设协议 |

如果锁定版本的关节电机不能可靠施加力矩上限，使用显式受限 PD 力矩控制，并用堵转案例验收。不要只设置目标姿态。

3D 距离查询首版是几何近似，不声称完整超声声学模型。接触和距离输入提供者由场景模式选择；2D raycast、手动面板与 3D 输入不能相互覆盖。控制器参数、命令值、实际值分开命名与显示。

线缆首版复用现有连接和弧线显示，安装端跟随场景挂点。默认不把 wire rope 加入机械求解；线长不足可提示，但拉力、拔脱和随碰撞断线另立阶段，避免影响运动测试基线。

## 8. 分阶段执行与完成条件

### P0 — 最小物理实验与版本核对（已完成）

- 用固定基座、动态连杆、旋转关节和方块验证锁定版本的驱动/力矩限制；采用 SI 单位。
- 验证无 WebGL 的运行世界可步进，确定刚体构建和时钟接口，记录性能基线。
- 完成条件：连杆能推动方块，固定障碍能阻止连杆到达目标，取消阻挡后恢复；结果不是写 transform 得到的动画。

### P1 — 可保存场景与基本运行控制（已完成）

- schema、版本、引用验证、显式从 assembly 创建场景；接入版本校验和自动保存。
- Physical Test 工作区、场景树、地面/基础体、刚体参数、Edit/Run/Pause/Step/Reset。
- 固定步进运行时、姿态所有权、单位 adapter、碰撞体显示。
- 完成条件：自由落体、叠放、摩擦滑动可运行；运行不污染初始姿态；保存重开并 Reset 后得到同一初始配置。

### P2 — 首条完整测试链：Servo 推物体（已完成）

- 接入 servo 模型的底座和运动件，配置轴/锚点、质量、关节限位、有限驱动力矩。
- 手动滑块控制、导入连杆挂载、接触记录、目标角/实际角曲线。
- 完成条件：加载内置案例即可测试推动、阻挡、解除阻挡；Pause/Step/Reset 工作，纯旋转不会被休眠逻辑漏掉。

### P3 — Stepper、DC motor 与机械交互（核心已完成）

- 加入滑动关节、stepper 目标步数与实际位置、DC motor 负载运动；扩展挂点编辑。
- 加入接触传感器、限位开关、3D 距离查询、受力拖拽。
- 完成条件：步进机构前进触发限位；DC motor 在增加负载后改变实际运动；传感器使用运行世界姿态。

### P4 — Arduino 闭环（已完成）

- 接入共同时间协调器、外设命令/反馈 adapter；同步开始、暂停、单步与重置。
- 构建“stepper 前进 → 触发限位 → sketch 停止/反向”和“距离变化 → sketch 调节 servo”案例。
- 完成条件：指令由实际 sketch 产生，反馈来自 3D 世界；重复运行通过断言；暂停 MCU 时机械世界不会继续前进。

### P5 — 回归测试、诊断与交付（核心已完成）

- 版本化测试案例、时间序列输入、容差断言、JSON/CSV 结果导出，包含场景/程序/引擎版本和参数。
- 配置 collider/joint/sensor 调试叠层；显示缺失资源、无效关节和无法满足的测试断言。
- 测试项目切换、加载失败、取消运行、场景删除、资源重载和运行中编辑策略。
- 完成条件：下列验收案例全部通过；旧 2D/3D 编辑、程序保存和现有物理开关路径无回归。新入口稳定后再决定整合旧开关。

P2 是首个可体验交付点；P4 完成 Arduino 交互目标；P5 后才视为本计划完成。

## 9. 验收案例与性能预算

| 案例 | 核心断言 |
| --- | --- |
| 自由落体/落地 | 碰撞前接近解析重力轨迹；落地不穿透、不产生 NaN |
| Servo sweep | 无负载达到目标容差；碰撞固定挡块时保持受限且有跟随误差 |
| Servo push | 动态方块被推动；增加质量后运动响应改变 |
| Stepper limit | 输入步数不丢计数；实际机构触发限位，控制程序在规定反馈时限内响应 |
| DC load | 固定输入下增加规定负载，实际轴速/加速度按选定简化模型改变 |
| 3D distance | 已知距离场景测量在容差内；无目标返回无回波；移动后读数更新 |
| 导入凹形/偏轴模型 | 夹爪空隙可以通过物体；绕正确 pivot 运动；模型与碰撞体一致 |
| Reset/replay | 同一构建、参数和输入下结果在容差内复现；不承诺跨引擎版本逐 bit 一致 |
| Frame-rate independence | 30/60/120 渲染频率下，固定模拟时长的物理结果在同一容差内 |
| Persistence | Running/Paused 自动保存不写入临时姿态；旧项目迁移、重开和切换不丢配置 |

每个 fixture 固定尺寸、质量、时长、采样率与数值容差，禁止仅以“看起来正常”通过。初始容差候选：静态位置 0.5 mm、无负载关节角 1°；P0 根据步长与模型尺度验证后写入案例，不能为掩盖失败随意放宽。

首版基准场景：50 个动态刚体、20 个关节、10 个传感器，不含 wire rope。记录机器、浏览器、锁定引擎版本和模型复杂度，目标 60 FPS、机械 120 Hz；物理每显示帧 p95 预算 8 ms。预算不足优先简化 collider、减少无效查询，再评估 worker；不得静默改变步长或跳过模拟时间。

验证分层：schema/单位/引用测试；使用真实 Rapier 的无渲染行为测试；运行协调器的时序测试；工作区和保存/恢复浏览器集成测试；最后进行 GLB 对齐和交互视觉验收。

## 10. 与架构迁移计划的关系

- 复用现有 Board/asset 标识、版本校验和持久化机制，新增 scene 数据不得绕过冲突检测。
- 复用 `SimulationRuntime` 的生命周期思路，但现有实现只管理调度；不要把“已有 runtime”视为已解决机械与 MCU 同步。
- ProgramSource 归属计划继续独立推进；机械测试先支持 Manual，再通过程序读取 adapter 接入当前 sketch。
- physicalScene 的持久化与 runtime 分离是本计划的硬要求；Arduino/Scene 的目录/包物理拆分不是先决条件。
